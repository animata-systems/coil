# 03. Extended

| | |
|---|---|
| **Статус** | Смешанный: stable surface + experimental semantics (см. ниже) |
| **Назначение** | Расширения, вписанные в проектную модель |

---

## 3.1. Общий статус

Операторы Extended имеют разный нормативный статус:

| Оператор | Surface syntax | Семантика |
|---|---|---|
| `ЕСЛИ` | Stable | Stable (включая expression grammar) |
| `ПОВТОРЯЙ` | Stable | Stable (включая expression grammar) |
| `КАЖДЫЙ` | Stable | Stable |
| `СОБЕРИ` | Deferred | Deferred — сознательно не нормализуется в текущем цикле |
| `СИГНАЛ` | Stable | Experimental — зависит от stream semantics |

**Stable** означает: surface syntax заморожен, docs и examples могут этому учить, будущие истории вправе на это опираться.

**Experimental** означает: идея принята, но синтаксис или семантика ещё подвижны.

**Deferred** означает: область признана важной, но сознательно не нормализуется в текущем цикле.

---

## 3.2. `ЕСЛИ`

| | |
|---|---|
| **Статус** | Stable |

### Назначение

Условное ветвление. Управляет потоком исполнения на основе детерминированно вычисляемого условия.

### Каноническая форма

```coil
ЕСЛИ $score > 80
  ...
КОНЕЦ
```

```coil
ЕСЛИ НЕ ($verdict.type = "technical")
  ...
КОНЕЦ
```

### Семантика

- Условие вычисляется средой исполнения детерминированно, без вызова LLM.
- `ЕСЛИ` управляет потоком исполнения, а не формулировкой промпта.
- Синтаксис условия определяется грамматикой выражений (§ 3.7).

### Правила валидности

- Условие должно быть выражением, вычисляемым средой исполнения детерминированно, без вызова LLM.
- Условие должно соответствовать грамматике выражений (§ 3.7).

---

## 3.3. `ПОВТОРЯЙ`

| | |
|---|---|
| **Статус** | Stable |

### Назначение

Цикл с обязательным ограничением сверху.

### Канонические формы

Count-only форма:

```coil
ПОВТОРЯЙ 5
  ...
КОНЕЦ
```

Условная форма:

```coil
ПОВТОРЯЙ ДО $score >= 8 НЕ БОЛЕЕ 5
  ...
КОНЕЦ
```

### Семантика

- Тело цикла исполняется повторно, пока не достигнут лимит (count-only форма) или пока условие не выполнено либо не достигнут лимит (условная форма).
- Ограничение числа повторов — **часть конструкции**, а не внешняя договорённость.
- Обе формы являются каноническими. Count-only форма — не послабление, а полноценная конструкция.
- Условие в форме `ДО` должно соответствовать грамматике выражений (§ 3.7).

### Правила валидности

- Лимит повторов обязателен. `ПОВТОРЯЙ` без лимита считается невалидным.
- Условие в форме `ДО` должно быть выражением, вычисляемым средой исполнения детерминированно (§ 3.7).

---

## 3.4. `КАЖДЫЙ`

| | |
|---|---|
| **Статус** | Stable |

### Назначение

Итерация по элементам списка. Выполняет тело для каждого элемента.

### Рабочая форма

```coil
КАЖДЫЙ $task ИЗ $plan.files
  ...
КОНЕЦ
```

### Модификаторы

| ID | Ключевое слово (RU) | Назначение | Принимает | Обязательность |
|---|---|---|---|---|
| `Mod.From` | `ИЗ` | Источник — список для итерации | Ссылка `$name` | Да |

### Семантика

- Переменная элемента указывается в сигнатуре как `$name`.
- `ИЗ` принимает ссылку на значение типа `СПИСОК`.
- Итерации исполняются **последовательно**. Среда исполнения не вправе переупорядочивать или распараллеливать итерации.
- Итерация детерминирована: управление потоком без LLM.
- Каждая итерация создаёт **вложенный scope**. Переменная элемента, обещания и значения, созданные внутри итерации, изолированы: не видны за пределами цикла и не утекают между итерациями.

> Явная параллельная форма итерации — deferred (отдельная конструкция или модификатор).

### Правила валидности

- `ИЗ` обязателен.
- Источник должен быть значением типа `СПИСОК`.
- Переменная элемента не должна совпадать с уже определённым именем во внешнем scope.

### Ошибки

| Условие | Класс ошибки |
|---|---|
| Источник не является списком | Ошибка исполнения |
| `ИЗ` опущен | Ошибка подготовки |
| Имя переменной конфликтует с внешним scope | Ошибка подготовки |

## 3.5. `СОБЕРИ`

| | |
|---|---|
| **Статус** | Deferred |

### Назначение

Агрегация набора результатов в одно итоговое значение.

> `СОБЕРИ` сознательно не нормализуется в текущем цикле. Точный синтаксис не зафиксирован.

---

## 3.6. `СИГНАЛ`

| | |
|---|---|
| **Статус** | Stable (surface syntax и базовая семантика) |

### Назначение

Отправка данных в уже существующий поток. Не открывает новый поток.

### Каноническая форма

```coil
СИГНАЛ ~решение
<<
Клиент сообщил новый номер договора: $contract_id
>>
КОНЕЦ
```

### Семантика

- Адресат — уже существующий поток `~name`.
- Доставка асинхронная: сигнал помещается в буфер потока. Получатель принимает его в согласованной точке исполнения.
- Порядок доставки — FIFO: сигналы доставляются в порядке их отправки.
- `СИГНАЛ` после закрытия потока (после разрешения `?name`) считается ошибкой исполнения.

### Ошибки

| Условие | Класс ошибки |
|---|---|
| Поток `~name` не существует | Ошибка подготовки |
| Поток `~name` закрыт | Ошибка исполнения |

## 3.7. Грамматика выражений

| | |
|---|---|
| **Статус** | Stable |

### Назначение

Грамматика выражений определяет синтаксис и семантику условий в операторах `ЕСЛИ` и `ПОВТОРЯЙ ДО`. Выражения вычисляются средой исполнения детерминированно, без вызова LLM.

### Операнды

Допустимые операнды выражения:

| Операнд | Пример | Описание |
|---|---|---|
| Ссылка на значение | `$name` | Привязанное значение |
| Доступ к полю | `$name.a.b.c` | Цепочечный доступ к полям |
| Строковый литерал | `"technical"` | Строка в двойных кавычках |
| Числовой литерал | `42`, `3.14` | Целое или дробное число |
| Булев литерал | `ИСТИНА`, `ЛОЖЬ` | Логическая константа |

### Операторы сравнения

| Оператор | Описание | Допустимые типы операндов |
|---|---|---|
| `=` | Равенство (структурное) | Любые |
| `<` | Меньше | Только числа |
| `>` | Больше | Только числа |
| `<=` | Меньше или равно | Только числа |
| `>=` | Больше или равно | Только числа |

Оператор `=` выполняет структурное сравнение. Операторы `<`, `>`, `<=`, `>=` определены только для числовых значений.

Оператор `==` не является частью языка. Оператор `!=` не является частью языка; неравенство выражается через `НЕ ($x = значение)`.

Цепочечные сравнения (например, `1 < $x < 10`) запрещены.

### Логические связки

| Связка | Описание |
|---|---|
| `И` | Логическое «и» |
| `ИЛИ` | Логическое «или» |
| `НЕ` | Логическое отрицание |

### Приоритет

Приоритет от высшего к низшему:

1. `НЕ` (унарный)
2. Операторы сравнения (`=`, `<`, `>`, `<=`, `>=`)
3. `И`, `ИЛИ` (одинаковый приоритет)

Смешивание `И` и `ИЛИ` в одном выражении без скобок считается ошибкой подготовки. Группировка скобками разрешена и обязательна при комбинации `И` и `ИЛИ`.

### Примеры

```coil
ЕСЛИ $score >= 8
  ...
КОНЕЦ

ЕСЛИ $verdict.type = "technical"
  ...
КОНЕЦ

ЕСЛИ НЕ ($verdict.type = "general")
  ...
КОНЕЦ

ЕСЛИ $score > 5 И $category = "important"
  ...
КОНЕЦ

ЕСЛИ ($a > 1 И $b > 1) ИЛИ $override = ИСТИНА
  ...
КОНЕЦ
```

### Формы вне текущей нормы

Следующие формы не входят в грамматику выражений `v0.4` и считаются ошибкой подготовки:

- **Truthiness** — голая ссылка в позиции условия (`ЕСЛИ $done`) — deferred.
- **Арифметика** — вычислительные выражения (`$a + $b`) — deferred.
- **Вызовы функций** — deferred.
- **Implicit coercion** — неявное приведение типов — deferred.

## 3.8. Устаревшие формы

| Оператор | Статус | Замена |
|---|---|---|
| `ВЫЗОВИ` | Исключён | Объединён с `ВЫПОЛНИ` (Core). One-shot вызов — вырожденный случай `ВЫПОЛНИ` |
| `СПРОСИ` | Исключён | Роль поглощена `НАПИШИ` с модификатором `ЖДАТЬ` |
| `ОТВЕТЬ` | Исключён | Сообщения — `НАПИШИ`, завершение — `ВЫХОД` |
| `КАЖДЫЙ` | Восстановлен | Перенесён обратно в Extended (§ 3.4) |
| `СВЕДИ` | Исключён | Заменяется `СОБЕРИ` (если понадобится) |
