# COIL:zh-standard — 简体中文标准方言

> 「用你思考的语言写脚本。」

**状态：** 官方方言，包含在标准发行版中。

本方言将所有 COIL 构造映射为地道的简体中文。每个关键字都力求让中文使用者一目了然——无需编程背景，无需借助英文。中文的语义密度使得大多数关键字只需两个汉字，脚本因此格外紧凑。

---

## 设计原则

1. **简洁自然。** 关键字使用日常中文，不使用技术术语。`发送` 而非 `传输` —— 因为我们说「发消息」，不说「传输消息」。`最多` 而非 `超时` —— 因为「最多10分钟」是自然的中文。

2. **两字为主。** 中文的语义密度使得大多数关键字只需两个汉字。单字仅用于意义明确的功能词：`完`、`到`、`给`、`从`、`对`。

3. **无需变形。** 中文没有动词变位、时态或性数变化。每个关键字是固定的词汇形式，不会随上下文改变拼写。这是中文方言的天然优势。

4. **类别暗示。** 词语的含义暗示操作符的类别：阻塞型（`接收`、`等待`），启动型（`思考`、`执行`、`发送`），即时型（`定义`、`修改`）。

## Core 操作符

| ID | ZH | 语义 |
|---|---|---|
| `Op.Actors` | `参与者` | 声明协议的参与者。谁在场景中行动。 |
| `Op.Tools` | `工具` | 声明可用的工具。代理用什么来工作。 |
| `Op.Define` | `定义` | 创建一个新的命名值。如同数学中的定义。 |
| `Op.Set` | `修改` | 修改一个已有的值。不是 `定义` —— 值已经存在。 |
| `Op.Receive` | `接收` | 从环境阻塞式绑定值。协议暂停，等待环境提供值。 |
| `Op.Think` | `思考` | 启动一个 LLM 认知步骤。模型接到问题并进行思考。 |
| `Op.Execute` | `执行` | 调用一个工具。涵盖一次性调用和交互式会话。 |
| `Op.Send` | `发送` | 向频道发送一条消息。中文里说「发消息」，不说「写消息」—— 这是消息应用的自然用语。 |
| `Op.Wait` | `等待` | 同步点。阻塞直到承诺被兑现。 |
| `Op.Exit` | `结束` | 终止协议。一行，无参数。 |
| `Kw.End` | `完` | 关闭一个块。每个块操作符以 `完` 结束。单字——中文的简洁优势。 |

## 修饰符

### 模型配置（思考）

| ID | ZH | 语义 |
|---|---|---|
| `Mod.Via` | `通过` | 使用哪个 LLM 模型。`通过 $快速模型` —— 通过该模型处理任务。 |
| `Mod.As` | `作为` | 角色定义（技能）。`作为 $分析师` —— 以该专家身份思考。仅引用。 |
| `Mod.Using` | `使用` | LLM 可用的工具。`使用 !搜索, !计算` —— 模型可以调用这些工具。 |

### 任务陈述（思考）

| ID | ZH | 语义 |
|---|---|---|
| `Mod.Goal` | `目标` | 认知步骤的目的。我们想要达成什么。 |
| `Mod.Input` | `输入` | 问题陈述。需要处理的数据。 |
| `Mod.Context` | `背景` | 附加数据、背景信息、约束条件。不用 `上下文` —— `背景` 更自然。 |
| `Mod.Result` | `结果` | 结构化输出规格。LLM 必须确定什么。 |

### 寻址（发送）

| ID | ZH | 语义 |
|---|---|---|
| `Mod.To` | `到` | 频道地址。`到 #支持` —— 发送到该频道。中文里「发到群里」是最自然的说法。 |
| `Mod.For` | `给` | 收件人。`给 @专家` —— 这条消息给该参与者。中文里「发给他」是日常用语。 |
| `Mod.ReplyTo` | `回复` | 回复引用。回复的是哪条消息。 |
| `Mod.Await` | `等候` | 回复等待策略。`等候 任意` —— 等待至少一个回复。与 `等待`（操作符）区分——见注释。 |
| `Mod.Timeout` | `最多` | 超时。`最多 10分` —— 10分钟后放弃。 |

### 同步（等待）

| ID | ZH | 语义 |
|---|---|---|
| `Mod.On` | `对` | 等待的承诺。`对 ?计划, ?数据` —— 我们等待的是这些承诺。 |
| `Mod.Mode` | `模式` | 等待模式。需要多少个承诺被兑现。 |
| `Pol.All` | `全部` | 等待所有列出的承诺。 |
| `Pol.Any` | `任意` | 等待列出的承诺中的任意一个。 |
| `Pol.None` | `无` | 不等待回复。发了就忘。 |
| `Mod.Timeout` | `最多` | 超时。与发送中的关键字相同——保持一致。 |

### 工具调用（执行）

| ID | ZH | 语义 |
|---|---|---|
| `Mod.Using` | `使用` | 调用哪个工具。`使用 !搜索` —— 必填，恰好一个。 |

## Extended 操作符

| ID | ZH | 语义 |
|---|---|---|
| `Op.If` | `如果` | 条件分支。确定性的，不涉及 LLM。 |
| `Op.Repeat` | `重复` | 带强制上限的循环。`重复 5` 或 `重复 直到 $完成 最多 5`。 |
| `Op.Each` | `每个` | 遍历列表元素。`每个 $任务 从 $计划.文件`。确定性迭代。 |
| `Op.Gather` | `汇总` | 将结果汇总为单一值。 |
| `Op.Signal` | `信号` | 向已有的流发送数据。 |

### 迭代修饰符

| ID | ZH | 语义 |
|---|---|---|
| `Mod.Until` | `直到` | 循环退出条件。`重复 直到 $就绪 最多 5`。 |
| `Mod.Limit` | `最多` | 迭代上限（在重复中）。必填——没有上限的循环是无效的。 |
| `Mod.From` | `从` | 迭代的列表来源。`每个 $元素 从 $列表`。 |

## 上下文相关解析

`最多` 映射到两个抽象标识符。操作符上下文无歧义地决定适用哪一个：

| 关键字 | 上下文 | 抽象 ID |
|---|---|---|
| `最多` | 在 `发送` 或 `等待` 内部 | `Mod.Timeout` |
| `最多` | 在 `重复` 内部 | `Mod.Limit` |

「最多10分钟」（超时）和「最多5次」（迭代上限）—— 一个自然的中文词覆盖两种情况。

## 示例：研究代理

```coil
' ──────────────────────────────────────────────
' 环境
' ──────────────────────────────────────────────
参与者 专家, 作者
工具 搜索

' ──────────────────────────────────────────────
' 角色 —— LLM 的专业背景。
' 定义 LLM 在执行任务时应具备的
' 知识和方法。
' ──────────────────────────────────────────────
定义 研究技能
<<
你是一名研究分析师。
你处理非结构化查询。
你始终寻找一手资料，并标明
结论的可信度。你避免推测。
如果数据不足——你直说。
>>
完

定义 领域专长
<<
你精通产品分析。
你了解留存、激活和流失指标。
你能解读漏斗图和队列报告。
分析时，你始终区分
相关性和因果关系。
>>
完

' ──────────────────────────────────────────────
' 输入数据 —— 环境必须在协议继续之前
' 提供这些值。
' ──────────────────────────────────────────────
接收 查询
<<
用户的研究查询。
>>
完

接收 查询历史
<<
该主题的历史查询记录。
>>
完

接收 案例编号
<<
当前案例的标识符。
>>
完

' ──────────────────────────────────────────────
' 1. 任务陈述 —— 结构类似数学题：
'    作为   —— 角色 / 专家背景
'    目标   —— 想要达成什么
'    输入   —— 问题数据
'    背景   —— 背景信息
'    结果   —— 需要确定什么
'
' 思考 在后台运行。创建结果承诺
' ?分析 和实时流 ~分析。
' 输入可以在思考过程中通过 信号 补充。
' ──────────────────────────────────────────────
思考 分析
  作为 $研究技能, $领域专长
  目标 <<
  准备一份有据可查的回答。
  >>
  输入 <<
  研究用户的查询。将分析过程中
  通过流到达的所有数据纳入考量。
  >>
  背景 <<
  查询：$查询
  查询历史：$查询历史
  >>
  结果
  * 回答: 文本 - 最终回答
  * 来源: 列表 - 引用的参考资料
    * 链接: 文本 - 来源链接
    * 原因: 文本 - 为什么相关
  * 置信度: 选项(高, 中, 低)
完

' ──────────────────────────────────────────────
' 2. 数据收集 —— 与思考并行。
'    搜索和专家请求互不阻塞，
'    也不阻塞 思考。
' ──────────────────────────────────────────────
执行 已找到
  使用 !搜索
  - query: $查询
  - limit: 10
完

发送 意见
  到 #咨询
  给 @专家
  等候 任意
  最多 10分
  <<
  需要关于此查询的专家意见：$查询
  >>
完

' ──────────────────────────────────────────────
' 3. 在思考过程中补充输入。
'    数据以任意顺序到达——
'    每个结果立即注入 ~分析。
'    LLM 无需重启即可纳入。
' ──────────────────────────────────────────────
重复 2
  等待 数据
    对 ?已找到, ?意见
    模式 任意
  完

  信号 ~分析
    <<
    $数据
    >>
  完
完

' ──────────────────────────────────────────────
' 4. 分析完成。
'    结果综合了初始数据、
'    搜索结果和专家意见。
' ──────────────────────────────────────────────
等待
  对 ?分析
完

' ──────────────────────────────────────────────
' 5. 交付回答。
' ──────────────────────────────────────────────
发送
  到 #结果/$案例编号
  给 @作者
  <<
  $分析.回答
  >>
完

结束
```

## 注释

**为什么用 `完` 而非 `结束` 关闭块？**
`结束` 用于终止整个协议——这是最终的、不可逆的。`完` 用于关闭一个块——这是局部的、重复出现的。中文的 `完` 只有一个字，这使得 COIL 脚本在中文方言下特别紧凑。在所有方言中，中文是唯一使用单字块终结符的方言。

**为什么用 `发送` 而非 `写`？**
其他方言（俄语 НАПИШИ、德语 SCHREIBE、法语 ÉCRIS）选择了「写」，因为在那些语言中人们说「写给我」。但在中文里，我们说「发消息」「发到群里」「发给他」—— 动词是「发」，不是「写」。`发送` 反映了中文使用者的真实语言习惯。

**为什么时长后缀用 `秒`、`分`、`时` 而非 s、m、h？**
其他方言使用拉丁字母缩写，因为那是国际惯例。但中文有自己的单字时间单位。`最多 10分` 比 `最多 10m` 读起来更自然。这是中文方言独有的特点。
